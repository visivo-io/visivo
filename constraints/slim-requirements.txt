# The dependency set `visivo.agent.tools` needs, and nothing more.

# `pip install visivo` is unchanged and still full. This file is the other
# install mode: core's Django image imports the tool registry to serve MCP, and
# must not carry duckdb, polars or pyarrow -- they would sit in every web pod
# for code those pods never run.
#
#     pip install --no-deps visivo==<version> -r constraints/slim-requirements.txt
#
# Specifiers mirror pyproject.toml so the two cannot drift. Transitive
# dependencies are left to the resolver.
#
# tests/agent/test_slim_imports.py is what keeps this honest: a new module-level
# import of a heavy package fails there, not in a cloud deploy. Add to this file
# only after confirming the dependency cannot be deferred into the function that
# needs it.
#
# Deliberately absent: every warehouse driver. psycopg2, snowflake, redshift and
# bigquery are never imported by the registry. mysql_source and clickhouse_source
# do import theirs, but both already guard with `try/except ImportError`, so the
# modules load without them and only a connection attempt would fail -- which a
# web pod never makes.
